Translation pilot

Pebble Pit, 115 messages in eight languages, translated twice: A drafted by Claude to a style guide, and B machine-translated with Firefox Translations (Bergamot). Written 2026-10-13.

The short answer. On meaning and voice, the drafted version (A) is better in all eight languages, and the gap is widest in Japanese, Korean, Chinese and Russian. On word-for-word closeness to the English, the machine (B) scores higher, because it translates literally. The machine also makes errors no player should see: it misreads words with two meanings (save, scale, bolt), slips into the formal address, leaves English behind, and in Chinese and Japanese loses three of the numbers the game fills in. My recommendation is A for every language, with a native reviewer for each before anything ships. Use B only as a cross-check for omissions.

Read this with care: I wrote version A, and I also back-translated version B, so I am grading my own work. The checks below that do not rely on my judgment are the mechanical table and the Argos column, where a third engine that wrote neither version back-translates both.

What was compared

  • The sample. 115 messages from locales/en.ftl (docs/l10n-pilot/sample.txt lists each one and why it was picked). It covers every group except the index, which the owner is rewriting, and every hard case in the file: the plural, the ordinal, the nested select and the numeric-key selects; messages with one to four variables; both kinds of markup (<br> and the data-l10n-name spans); an attribute-only message; the achievement jokes (pylons, "you're a wizard", "shaken baby syndrome", "we're so back"); one-word buttons; long sentences; and every invented term. The [owner's words] placeholders are left out.
  • A, drafted. Written by Claude (Opus 5.5) to locales/STYLE.md: lowercase where the English is, informal address, the player never given a gender, jokes swapped for the local equivalent, and a glossary that renders sqwife and sqhusband as blends of each language's own words for "square" and "wife" or "husband". In docs/l10n-pilot/draft/. Written once and not edited after the back-translations came in, except to shorten five labels over the length budget (before any scoring).
  • B, machine. Firefox Translations: Mozilla's Bergamot models, the ones Firefox downloads, taken from its public Remote Settings model registry and run offline in node through @browsermt/bergamot-translator 0.4.9 (wasm). No account, no key, nothing scraped. Every language was available. Fluent was protected: each select is split into whole sentences, one per plural category of the target language, with a number from that category put in so the engine inflects for it; every variable and markup element goes in as a number and comes back as itself; the selects are then rebuilt. The only post-edits are first-letter case and leaving the game's name alone. In docs/l10n-pilot/machine/.
  • The referees. Each version is back-translated by something that did not write it: A by Bergamot, B by me, literally, with errors kept and notes in [brackets]. Then a third engine, Argos Translate (OpenNMT models from the Argos index, offline), back-translates both. That column is the only symmetric one. Argos has no usable Spanish model (es→en 1.9 repeats one token forever under the installed CTranslate2, so Spanish has no Argos score), and its Japanese and Korean models (1.1) are small and noisy, which pulls both versions' scores down there. Scores are chrF (character n-gram F-score, 0 to 100) against the English, with variables filled the same way on both sides (a number is 5, a word is X).

Mechanical checks

Every file was parsed with the strict @fluent/syntax parser and the runtime @fluent/bundle. Then: does every variable the English shows reach every translated line; is the markup identical; are the plural keys the language's own CLDR categories; is any English left (a line identical to the English, or English words in it, not counting true cognates); and are labels up to 20 columns more than 40% longer (a CJK character counts as two columns, as in the game's monospace face).

What these numbers do and do not say. Back-translation rewards literalness, not voice. A translation that turns "it never rains but it pours" into the local proverb is right, and it scores low, because the proverb comes back as different English. A translation that copies the English word for word is wrong in the language, and it scores high, because it comes back as the same English. B is literal by nature, so B leads on every column here. That lead is real, but it measures closeness to the English words, not correctness.

The grey columns are not symmetric. A was back-translated by an engine that adds its own errors ("Spielstände" came back as "Playstands"). B was back-translated by me, and I know the English, which pulls B's back-translation toward the source. "B, its own engine" shows how far an engine flatters its own output on a round trip. Only the two Argos columns use the same referee for both versions.

The full file

Recommendation: draft all 964 messages (minus the owner's placeholders and the index being rewritten) as version A, to locales/STYLE.md, in every language. Then:

  1. The owner approves the glossary first: above all the sqwife and sqhusband blends, which appear on the rescue sheet, the objectives and the books, and the German all-lowercase nouns. Changing a term after 964 lines are written costs a re-pass.
  2. Draft in batches by group (sheets, boards, crew, the deep…), about 120 messages per batch per language. This pilot took one sitting for 115 × 8. The rest is about eight such passes, plus a consistency pass per language against the glossary.
  3. Run the pilot's checks on every batch: check.mjs (parse, variables, markup, CLDR keys, English left, length) catches the mechanical failures automatically. Run Bergamot over the same batch as a second opinion only: a line where A's Bergamot back-translation drifts far from the English is worth a second look for an omission. Never let B's text replace A's.
  4. A native reviewer per language (DESIGN.md, phase two) reads the drafts with the English comments beside them before anything ships. The pilot's own uncertain calls, marked in the notes: the localized StarCraft pylon line in German and Portuguese, the "potion seller" meme everywhere, French non-breaking spaces before : ? !, and whether neutral Spanish should lean Latin American.
  5. What the words cannot fix: the casino marquee and the number font draw only ASCII capitals (no Ü, Á, Ё, nor any CJK), so casino-drop and serp-level need glyphs drawn (DESIGN.md, Faces). $name, $who and $place arrive in the nominative case, so German, Russian and Korean lines around them have to be worded to fit. A Fluent term or a case attribute per name would fix that properly, and it is a design decision for the owner.

Reproducing it

All tools are in docs/l10n-pilot/tools/. Their packages and the models stay outside the repo (PILOT_DEPS, MODELS_DIR, ARGOS_PACKAGES_DIR). The order: models.mjs (fetch the Bergamot models), english.mjs, machine.mjs <lang>, annotate.mjs <lang>, check.mjs, back.mjs <lang> [machine], argos_back.py, score.mjs, report.mjs. The bergamot-translator 0.4.9 npm package needs two local patches to run in node on Windows: a {"type":"commonjs"} package.json in its worker/ folder, and pathToFileURL/fileURLToPath for the worker's own location. Its default registry splits zh-Hans wrongly, which engine.mjs works around.
