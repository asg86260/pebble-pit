Controls page

Three ways to redo the settings sheet's controls page. Every input and action word is the game's existing message (locales/en.ftl, ctl-*); the actions drop the caps and wide tracking so they can wrap inside the sheet. Words marked with a dotted underline and * are new and are the owner's to name. Each option is drawn at the held sheet's desktop width (36em, 432px inside) and at a 360px phone.

Mouse and keys on one tab, the controller on the other; each a plain two-column list, input then action. Pad buttons drawn at 22px as their real shapes.

What the mock cannot show
  • The real font on your machine, or other languages: German or French actions run longer and will wrap more, and CJK takes its own face.
  • The PlayStation family: the game swaps the face letters for ✕ ○ □ △ (padread.js). Every option here keeps the same shapes, so that swap still works; only the mark inside changes.
  • The pad's focus marker moving over the rows, the page's fade-in, or scrolling on a short window (option C's desktop page is the tallest).
  • Group headings (B) and tab names (A) are new words with no message yet; the X row ("cancel a purchase") is a placeholder for an action another change is adding.
  • The left stick has no row on the page today, so option C leaves it unlabeled.
  • Whether the pad half should hide until a pad is seen, as the page does today. A and B could show it always; C is mostly pad.
Flag: Y already reads "hand back a queued copy". If the X "cancel a purchase" being added is the same act (handing back a queued copy refunds it), the page would list one action twice; either X replaces Y's row, or one of the two words changes.
