A name on a gamepad

  • On Steam (the desk build, a Deck or Big Picture): Steam's own keyboard over the field (Steamworks' floating gamepad text input). Nothing to draw, but only there.
  • Everywhere else: the letter grid under the name row in the mock (switch "input" to gamepad above). The d-pad walks it, A types, X is backspace, Y randomizes the row the focus is on. The grid is the source locale's letters; a CJK or Cyrillic grid is a separate drawing per language.
  • Randomize everything (the owner, 2026-10-16): a die on every row (name, role, each of the five slots) rolls that row alone, and randomize all rolls the whole square. A random name is drawn from a name list: the mock's four are [name 1] to [name 4], placeholders; the list is the owner's to write. A pad player who never types still leaves with a name.

In Fluent: the mechanism

src/lang.js runs @fluent/bundle 0.19.1; selectors are already in every locale. The game hands over the role as a key and the name as a plain string: msg('obj-rock', { so: 'wife', soName: 'pat' }). A name needs no article and no case, so a named line mostly dodges gender; what is left is the pronouns and the agreeing verbs and adjectives.

# en: the name when there is one, else today's words by role
obj-rock = dig the boulder to save { $soName ->
    [none] your { $so ->
        [wife] sqwife
       *[husband] sqhusband
    }
   *[other] { $soName }
}!
idx-sqwife-text = living { $so ->
    [wife] her
   *[husband] his
} life, until the incident(s), stuck under infinitely falling boulders from the sky. crazy.

# de: the role form declines (deine frau / deinen mann); the named form does not
obj-rescue = rette { $soName ->
    [none] { $so ->
        [wife] deine frau
       *[husband] deinen mann
    }
   *[other] { $soName }
}

# ru: named or not, the participle still agrees with the role
ach-gotout-name = { $soName ->
    [none] { $so -> [wife] жена *[husband] муж }
   *[other] { $soName }
} { $so -> [wife] спасена *[husband] спасён }

The [none] arm needs the game to pass the string "none" for an empty name (Fluent cannot test for an empty string), and a player who names their square "none" would hit it: a reason to pass a separate $named key instead. A detail for the build, not the vote.

What the mock cannot show
